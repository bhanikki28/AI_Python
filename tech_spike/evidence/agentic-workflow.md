## Where I intervened

1. **Scope and use case.** I chose PII Gate from three options. I stopped the agent ("wait..") and asked for an explanation of the agentic features before any further changes. Then I constrained the LLM to be **optional**, so the assessors and I need nothing beyond Python.
2. **Ownership of commits.** The agent committed Phase 0 itself. I asked to do it myself, and it undid its local, unpushed commit with `git reset --mixed`. From then on it left changes unstaged with a suggested message. That's why the history shows my commits phase by phase.
3. **Gate between phases.** Each phase was reviewed (file list, `make verify` output, the agent's stated caveats) before I approved the next.
4. **CI confirmation.** I pushed Phase 7 and shared the Actions screenshot. The agent then checked the per-job logs with `gh` rather than relying on the green tick.

## How generated output was reviewed and verified

- **Every phase ended with `make verify`**, and with a real run where it mattered: a live uvicorn server with curl, a real MCP stdio session, a real `docker build` and smoke test, and the CLI with no Ollama present.
- **Evals as a backstop, not decoration.** The agent read the failure list even when all thresholds passed, which surfaced 2 real bugs.
- **Library facts checked against installed source, not memory.** The `mcp` SDK had moved to 2.x (`FastMCP` renamed to `MCPServer`, structured output behaviour changed). The agent read the installed package and ran a small experiment before writing code.
- **Privacy assertions are tests, not claims:**
  - no input echo in 422 responses;
  - no PII in logs (caplog test, a grep of the live server log, and a grep of container logs in the smoke test);
  - the LLM request body contains no raw PII.

## Issues caught along the way (and by what)

| Issue | Caught by | Fix |
|---|---|---|
| 2 wrong test expectations (input length, email/digit boundary) | first `pytest` run | tests corrected; behaviour was right |
| BSB vs account mislabel; hyphenated dates flagged | **eval failure list** | nearest-keyword ranking; date-shape exclusion + regression tests |
| FastAPI 422 handler echoes the request body (PII leak in errors) | agent design review | custom handler + test |
| `mcp` 2.x API change; `dict` tool output not structured | import error; experiment | `MCPServer`, `structured_output=True`, major-version pin |
| "customer's" produced a stray `s` token that mis-ranked retrieval | `make mcp-demo` output | possessive stripping + regression test |
| Policy path wrong when installed as a wheel in Docker | agent anticipated it; smoke test confirms | `PII_GATE_POLICY_DIR` in image |
| Stray empty file `degraded` created by an agent shell command | `git status` review | inspected, then deleted |

## Where the agent was wrong (for transparency)

- It **committed Phase 0 without being asked to let me commit**. It was reverted before push (see intervention 2).
- Its Phase 1 summary **listed AU addresses**, contradicting `intent.md` (out of scope). It flagged this itself and didn't build it.
- It stated the policy had **16 clauses**; `/health` showed **15**. Corrected in the Phase 4 summary.
- It was **candid that the LLM path is untested against a real model**. That's recorded as a gap, not hidden.
